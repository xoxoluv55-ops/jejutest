## 1. CH1 뼈 그래픽 → 실제 해부학 모델 (BodyParts3D 4.0)
- **렌더링:** `tools/anatomy3d/ch1_bones.py`가 BodyParts3D 4.0 메시를 직접 렌더링합니다(three.js, CH2 판과 같은 셰이더).
  - 팔뼈 5개: 빗장뼈 FJ3362, 어깨뼈 FJ3384, 위팔뼈 FJ3368, 노뼈 FJ3349, 자뼈 FJ3391
  - 오른쪽 종아리뼈 FJ3366
  - 맥락용 뼈대: 복장뼈, 갈비뼈, 갈비연골, 손뼈
- **좌표:** CH2 판과 같은 앞면 좌표계를 씁니다(760×1260, 오른팔, 화면 왼쪽 = 가쪽).
  - 그래서 뼈 사이의 상대 위치는 모델에서 측정한 값 그대로입니다.
  - 종아리뼈만 다리에서 아래팔 옆으로 평행이동해 같은 축척으로 렌더링했습니다.
- **이미지 파일:** `app/public/assets/ch1/`
  - 뼈별 이미지(`bone_<id>.webp`)
  - 맥락 뼈대(`ctx.webp`)
  - `bones.json`: 뼈별 영역, 터치 판정용 불투명 표본점, 측정 랜드마크
- **측정 랜드마크:**
  - 위팔뼈머리 중심(구면 맞춤)
  - 관절오목
  - 팔꿈치
  - 어깨뼈의 봉우리·부리돌기·관절오목·아래각
- **적용 범위:** 뼈대 조립, 관절 정렬, 월드의 뼈, 인벤토리, 식별 창, 도감, 복구 테이블 연출 모두 모델 이미지를 씁니다.
- **조립 화면:**
  - 왼쪽 조립 대상은 **반투명한 실제 뼈 모델**입니다. 기초는 진하게 보이고 그룹 색이 은은하게 깔리며, 심화는 옅게 보입니다.
  - 정답 위치에 놓으면 **불투명하게 복원**됩니다.
  - 겹치는 순서는 앞면 기준(어깨뼈 → 자뼈 → 위팔뼈 → 노뼈 → 빗장뼈)입니다.
  - 배경 홀로그램은 모델의 갈비뼈·복장뼈·손뼈입니다.
- **확대 관찰:** 카드의 돋보기를 누르면 열립니다.
  - 뼈가 크게 보이고 몸쪽/먼쪽, 가쪽/안쪽 방향이 표시됩니다.
  - 기초는 관찰 포인트(특징 설명)를 보여 주고, 심화는 관찰 질문만 보여 줍니다.
- **판정:** 뼈 영역은 모델 렌더의 실제 불투명 영역(6단위 격자 표본점)으로 판정합니다.
- **방향 검증:**
  - 노뼈가 가쪽(화면 왼쪽), 자뼈가 안쪽입니다.
  - 위팔뼈머리는 관절오목의 가쪽에서 만납니다.
  - 빗장뼈 안쪽 끝은 복장뼈 쪽입니다.
  - 모두 모델 원본 좌표 그대로입니다.
- **예외 (X-ray):** X-ray 판독 퍼즐(X-04)의 필름은 **예전에 도형으로 그린 그림 그대로**입니다.
  - 필름 위 표시 지점이 그 그림에 맞춰져 있어 이번에는 바꾸지 않았습니다.
  - 모델로 방사선 사진을 렌더링하는 작업은 다음 단계 과제입니다.

## 2. 탐색 방식 변경
- **SCAN 제거**
  - SCAN 버튼과 Space 키를 없앴습니다.
  - CH2에서 SCAN으로만 보이던 근육 코어 2개는 처음부터 보이도록 바꿨습니다. 그대로 두면 CH2를 끝낼 수 없습니다.
  - CH2 코어를 얻는 방식(다가가서 조작 버튼)은 아직 그대로입니다. CH2 방탈출화는 아직 하지 않았습니다.
- **조사 가능한 물체**
  - 은은하게 반짝이는 표시로 구별됩니다.
  - 다가가서 조작(눈 아이콘)을 누르면 **확대 조사 화면**으로 전환됩니다.
  - 조사하는 동안 월드는 멈추므로 피해를 받지 않습니다.
  - 시작 통로(B-02)의 방전·증기 함정을 치워 퍼즐 구역을 안전 구역으로 만들었습니다.

## 3. 어깨뼈 퍼즐 (B-02 격리 통로)
흐름: 탐색 → 책상 조사 → 일지·메모 발견 → 액자 사진 + 뒷면 → 비밀번호 → 서랍 → 이중 바닥 → 표본 → 도감 → 격벽 개방

| 물체 | 조작 | 얻는 단서 |
|---|---|---|
| 연구원 책상 › 일지 | 눌러서 펼치고, 페이지 모서리를 눌러 넘김 | 마지막 장: 비밀번호를 읽는 **구조 순서**(봉우리 → 부리돌기 → 관절오목 → 아래각). 기초는 각 구조의 생김새 설명이 붙고, 심화는 이름만 나옵니다. |
| 책상 › 머그잔 | 들어 올림 | 아래의 메모: "숫자는 사진, 순서는 일지" |
| 벽 액자 | 사진 관찰 · 뒤집기 | 앞면: **실제 어깨뼈 모델 사진**에서 네 구조 위에 번호 스티커가 붙어 있습니다(위치는 메시에서 측정). 뒷면: "순서는 일지 마지막 장에" |
| 책상 › 서랍 | 키패드에 4자리 입력 | 틀리면 경고음, 몇 번이든 다시 시도할 수 있습니다. |
| 열린 서랍 | 바닥판 오른쪽 홈을 잡고 위로 끌기 (눌러도 됨) | 이중 바닥 → 표본 케이스 |
| 표본 케이스 | 꺼내기 | 어깨뼈 회수 + 도감 등록, 압력 센서가 해제되어 **B-02 → A-01 격벽이 열립니다** |

- **비밀번호:** 매 판 무작위 4자리입니다(숫자 중복 없음). 일지와 액자는 어느 쪽을 먼저 조사해도 됩니다.
- **해부학이 풀이 그 자체입니다.** 사진에서 봉우리·부리돌기·관절오목·아래각을 구별해야 숫자를 읽을 수 있습니다.
- **기록장:** 찾은 단서는 기록장에 저장되고 죽어도 유지됩니다(`G.run.clues`). 키패드에서도 기록장을 열 수 있고, 기록장에는 스티커가 붙은 사진 사본이 들어 있습니다.
- **단계적 힌트:**
  - 놓친 물건 → 비밀번호 규칙 → 사진에서 각 구조를 찾는 법
  - 기초는 마지막에 앞 두 자리를 알려 줍니다. 심화는 거기까지 주지 않습니다.
  - 열린 서랍 앞에서는 이중 바닥 힌트가 먼저 나옵니다.
- **그래픽:** 책상·일지·머그잔·메모·서랍·표본 케이스·액자는 `art/office.ts`에서 코드로 그렸습니다. 일러스트 에셋은 아닙니다. 사진과 케이스 속 뼈는 실제 모델 렌더입니다.

## 4. 검증 범위
- **헤드리스 Chromium, 1180×740** (실제 iPad에서는 확인하지 않음)
  - 어깨뼈 퍼즐 전체를 **실제 터치 좌표 입력**으로 진행했습니다. 오답 입력과 무제한 재시도, 순서를 바꾼 조사, 기록장, 힌트를 포함합니다.
  - 도감 저장(localStorage)과 격벽 개방을 확인했습니다.
- **막힘 상태 점검**
  - 비밀번호는 기록장의 사진 사본과 일지 순서만으로 항상 알 수 있습니다.
  - 퍼즐 구역에는 피해 요소가 없습니다.
  - 조사 화면은 언제든 나갔다가 다시 들어올 수 있습니다.
  - 표본을 꺼낸 뒤에는 서랍이 비어 있다고 표시됩니다.
- **저장 데이터:** 형식은 바뀌지 않았습니다(`anatomy-escape-save-v1`). 단서와 비밀번호는 한 판 안에서만 쓰는 값입니다.

## 5. 나머지 네 뼈 퍼즐 (v0.8)

모든 퍼즐에 공통으로 적용되는 원칙:
- **진행 순서:** B-02 격벽이 열린 뒤에는 어떤 순서로 풀어도 됩니다.
- **단서 연결:** 각 퍼즐의 단서는 다른 방의 물체에 있습니다.
- **조사 중 안전:** 조사 화면이 열려 있는 동안 월드가 멈춥니다.
- **오답:** 몇 번이든 다시 시도할 수 있습니다. 피해는 없고 실수 횟수만 기록됩니다.
- **기초 / 심화 차이:**
  - 기초에는 구조 설명이 붙고, 마지막 힌트가 정답을 알려 줍니다.
  - 심화에는 이름만 나오고, 힌트도 정답까지는 주지 않습니다.

### S-02 위팔뼈 — 온도 기록 → 냉각 장치 (V-05 보관동, 드론 경비 구역)

| 물체 | 조작 | 단서 / 결과 |
|---|---|---|
| 보관동 문가의 클립보드 | 맨 위 메모를 넘김(모서리를 누르거나 위로 끌기) | 메모: "마지막으로 '정상' 판정을 받은 날의 설정으로 해동" · 기록표: 4일치 × 3구역(머리·몸통·관절융기) 온도와 판정 |
| 냉각 캡슐 제어 장치 | 구역 A·B·C 슬라이더를 끌기(트랙을 누르면 2°씩 이동) → 해동 레버를 아래로 끌기 | 각 구역의 선은 **실제 위팔뼈 모델의 측정 지점**(위팔뼈머리, 몸통 중앙, 두 위관절융기의 중점)에 이어져 있습니다. 구역과 글자의 대응은 판마다 무작위입니다. |

- **오답 피드백:** 입력한 설정이 다른 날의 기록과 같으면 "11월 1일 기록과 같다(정상). 그날이 마지막 '정상'이었을까?"처럼 추론을 돕는 피드백이 나옵니다.
- **환경 변화:** 캡슐이 해동되면 소리를 들은 경비 드론이 캡슐 쪽으로 이동합니다.

### 6.2 X-ray: 3D 뼈 모델로 계산한 모의 방사선 영상
- **계산 방법(`tools/anatomy3d/xray_render.py`)**
  - BodyParts3D 메시(위팔뼈, 어깨뼈, 빗장뼈, 복장뼈, 갈비뼈)를 앞→뒤 평행 광선으로 통과시켜 **광선이 뼈를 지나는 길이**를 계산합니다.
  - 겉질뼈 껍질(표면에서 안쪽으로 2.2 mm) = 1.0, 해면뼈 내부 = 0.32로 두어 겉질 가장자리는 밝고 골수공간은 어둡게 나옵니다.
  - 감쇠는 1 − exp(−μ·d)로 계산합니다. 얇은 갈비뼈·복장뼈는 가중치를 낮췄습니다.
- **판독 표지:** 위치는 모델에서 측정한 봉우리, 부리돌기, 관절오목, 위팔뼈머리, 큰결절입니다.
- **비교 겹쳐 보기(기초):** 같은 좌표의 실제 뼈 모델을 겹쳐 보여 줍니다.
- **표시 문구:** 영상에 "모의 방사선 영상 · 3D 뼈 모델로 계산 · 실제 환자 영상 아님"을 표시합니다.
- **사용하지 않은 것:** 실제 환자 방사선 영상은 쓰지 않았습니다. 사용 허가를 확인할 수 있는 공개 영상을 확보하지 못했기 때문입니다.

### 6.5 CH2 '계속' 버튼·결과 화면 전환 시간 초과: 원인 확인
- **측정:** 헤드리스 실행에 계측(0.5초마다 프레임률, 실제 시간 대비 게임 시간, 활성 장면 목록)을 넣었습니다(`ch2diag.cjs`).
- **측정 결과**
  - 프레임률 중앙값은 3.35 fps였고, 714개 표본 중 550개에서 한 프레임이 200 ms를 넘었습니다.
  - Phaser는 5 fps 아래에서 프레임당 시간을 200 ms로 제한하고 평균을 냅니다. 그래서 게임 시계가 실제 시간의 약 25%로 흘렀습니다(실제 프레임 중앙값 367 ms, 게임 프레임 중앙값 90 ms).
  - 그 결과 개념 카드 지연, 승강기 연출 같은 게임 시간 기준 타이머가 실제로는 약 4배 길어졌습니다.
- **장면 로그에서 찾은 원인:** **Title 장면이 CH2 내내 함께 실행되고 있었습니다** (`Title,Game2,HUD` … `Title,Result`).
  - 테스트가 Boot가 끝나기 전(2.5초 시점, Title은 아직 대기 상태)에 챕터를 시작했습니다.
  - Boot가 끝난 뒤 무조건 Title을 시작해서 Title이 게임 뒤에서 계속 렌더링됐고, 그만큼 프레임률이 더 떨어졌습니다.
  - 실제 플레이에서는 타이틀 화면을 거쳐야 하므로 이 순서가 생기지 않습니다. 정상 경로에서는 Title이 종료되는 것을 확인했습니다(상태 8 = 종료).
- **수정**
  - Boot는 다른 장면이 이미 실행 중이면 Title을 시작하지 않습니다.
  - 테스트는 타이틀 화면이 뜬 것을 확인한 뒤 시작하고, 고정 시간 대신 게임 상태를 기다립니다.
- **실제 기기:** 일반적인 60 fps 환경에서는 게임 시계가 느려지지 않습니다. 5 fps 아래로 떨어지는 기기에서만 연출이 느려집니다.
- **CH1 시간 초과도 계측(0.5초마다 busy·전원 상태·위치·활성 장면 로그)으로 원인을 확인했습니다.**
  - **`!busy` 대기:** 차단기 조작은 정상 작동했습니다(게임 시간 1.9초, 실제 8초 뒤 전원 복구).
    - 이어서 정렬 장치를 조작하면 게임이 정상적으로 busy 상태가 되고, 장면 실행 지연 뒤 Align이 뜹니다.
    - 테스트의 재시도 분기는 Align이 아직 뜨기 전에 'busy 해제'를 20초 기다렸습니다. 퍼즐이 열려 있는 동안 busy는 풀리지 않으므로 반드시 시간 초과가 납니다. 테스트 쪽 논리 오류입니다.
  - **자뼈 케이지 화면 닫힘 대기:** 닫히기 전 연출 1.5초(게임 시간)가 느린 시계에서 실제 7초를 넘겨 테스트 한도 8초에 걸렸습니다.
  - 두 경우 모두 테스트를 고쳤습니다(게임 상태 기준으로 대기, 한도 연장).
