# NERVE RUNNER 3.0 — STEP 1 프로젝트 진단

대상: `web/src/*` → `web/build.py`가 만드는 `web/index.html` / `dist/nerve_runner.html`(= 공유된 NERVE RUNNER HTML, 2.6 버전).
규모: core.js 527줄 · app.js 750줄 · world.js 515줄 · star.js 71줄 · style.css 234줄 · body.html 149줄. 문제 64개 · 도감 56개 · 스토리 23개(JSON 9개 챕터).

검증 방법(이 환경에서 가능한 것만): Node 규칙 테스트(`web/test/sim_test.js`, 9개 스테이지 × 정답/오답/무입력 자동 주행), 헤드리스 Chromium(SwiftShader 소프트웨어 렌더) 스모크·자동주행·스크린샷(`web/test/pw_test.js`). **실제 iPad/iPhone 기기 테스트와 FPS 측정은 할 수 없음** — 아래 성능 항목은 코드 분석에 근거한 추정.

## 2. 구현은 되어 있지만 개선이 필요한 기능
- **좌우 이동**: `vx`를 60 m/s²로 선형 추종 → 버튼을 떼거나 반대로 누를 때 꺾이는 느낌. 관성·감속 곡선 없음. 터치는 디지털 버튼뿐(아날로그 조향 없음).
- **드리프트**: 성공/실패가 구분되지 않음(티어 0으로 놓으면 아무 일도 없음), 바닥 스파크·잔상 없음.
- **점프**: 상승/하강 중력이 같아 둥실거림, 그림자가 없어 착지 지점이 안 보임, 착지 효과 없음(`SE.Land` 이벤트는 발생하지만 처리 코드 없음).
- **부스트**: FOV 변화 외 속도선·전용 사운드 없음.
- **충돌 피드백**: 카메라 흔들림 0.9로 큼(멀미 요인), 별이 번쩍이거나 찌그러지지 않음.
- **연속 액션 보상 없음**: `SE.ObstacleDodged`가 발생하지만 아무도 받지 않음 → 회피해도 보상 없음. 콤보·점수 없음.
- **코너 예고 없음**: 급커브를 미리 알 수 있는 표지가 없음.
- **오브**: 매 프레임 모든 오브 행렬을 다시 계산(회전 연출용).
- **챕터 차별화**: CH.2–6, 8은 같은 `quizCourse` 템플릿(배경색·장식만 다름) → STEP 6 대상.
- **보스전**: 정답 게이트 5개 + 반격 파동 → STEP 7 대상.
- **시냅스 미니게임**: 버튼 순서 맞히기(타이밍 액션 아님) → STEP 4 대상.

## 3. 충돌·중복 코드
- 테마 색 표가 `world.js THEME` 하나로 정리됨(이전 app.js 사본 제거됨) — 중복 없음. 단 차선 색 `LANE`이 world.js와 CSS에 따로 있음.
- `hint()`와 구간 음성(`integ:*`)이 같은 순간 둘 다 말하려 함 → 뒤의 것이 앞의 것을 끊음(의도된 동작이지만 정리 필요).
- 대화창 AUTO 진행 코드가 선언 전 변수를 클로저로 참조(`l_ref`) — 동작은 하지만 위험한 패턴.
- 슬로모션 표시(`#h-slow`)와 문제 띠가 같은 위치 근처 — 문제 띠가 뜨면 숨기도록 처리됨.

## 4. 사용하지 않는 코드
- `save.storySeen`, `sim.ringBest`, `sim.steerSensitivity`(설정 UI 없음), `NR.CH9_BOSS` export, `SE.DriftStart`/`SE.Land`/`SE.ObstacleDodged`/`SE.Checkpoint` 일부 미처리.
- `Tools/VisualPreview`의 1.0 별(`starV1`)은 웹 빌드에 포함되지 않음(문제 없음).

## 5. 성능 저하 가능성 (추정 — 기기 측정 아님)
1. **매 프레임 객체 생성(GC 끊김 원인 후보 1순위)**: 이온 입자 240개 × `seg.worldPos()`(내부에서 객체 여러 개 생성), `frameAt()`(Vector3·Quaternion·Matrix4 생성) 별·카메라에서 매 프레임, 오브 회전용 `new Euler`. iOS Safari는 GC 멈춤이 화면 끊김으로 보이기 쉬움.
2. 오브 InstancedMesh 전체 행렬을 매 프레임 갱신(스테이지당 수십~백여 개).
3. 반투명 세포막 터널이 화면 대부분을 덮음(오버드로) + 블룸 → 모바일 GPU 부담. (2.5에서 폰은 블룸 기본 끔, FPS 감시로 자동 하향.)
4. 라벨 캔버스 텍스처가 게이트·포털마다 새로 생성(스테이지 전환 시 dispose는 됨).
5. HUD DOM 갱신은 2.5에서 "바뀔 때만"으로 개선됨.

## 7. 개선 계획 (단계)
- **STEP 2 (이번)**: 이동 관성, 아날로그 드래그 조향, 드리프트 성공/실패, 비대칭 점프 + 착지, 부스트 체감, 카메라 흔들림 완화, 매 프레임 할당 제거.
- **STEP 3 (이번, 효과 큰 것부터)**: 별 애니메이션(부스트 시 끝이 뒤로 휨·충돌 찌그러짐·정답 점프·오답 도리도리), 바닥 그림자, 드리프트 스파크 꼬리, 속도선, 코너 예고 표지, 콤보 HUD, 효과음 세분화.
- STEP 4: 1챕터 완성(도약전도 타이밍, EPSP/IPSP 공간적 가중, 시냅스 타이밍 액션).
- STEP 5: 플레이 테스트·수정 / STEP 6: 챕터별 전용 미션 / STEP 7: 보스 3페이즈·성장 시스템.
