# 협동 플레이 설계 — Supabase Realtime (PHASE 3)

> **상태: 설계만 완료. 코드는 아직 구현하지 않았습니다.** 게임 안의 MULTIPLAYER 버튼도 "PHASE 3 예정" 안내만 보여 줍니다.

## 1. 왜 Supabase Realtime인가
- 게임은 GitHub Pages(정적 호스팅)에 올라가므로 별도 게임 서버를 운영하지 않고 동기화할 수 있어야 함.
- Realtime **Broadcast**(저지연 메시지), **Presence**(접속·준비 상태), **Postgres**(방 상태 저장·재접속)를 한 서비스에서 제공.
- 클라이언트 라이브러리 `@supabase/supabase-js` 하나로 iPad Safari·PC 모두 WebSocket으로 동작.

## 2. 구조

```
[클라이언트 A(호스트)] ─┐
[클라이언트 B]        ├─ Realtime 채널  room:<입장코드>
[클라이언트 C/D]      ┘     ├ presence : 플레이어 목록·색상·준비·역할
                            ├ broadcast: pos / act / puzzle / sync
                            └ (Postgres) rooms 테이블: 마지막 확정 상태 스냅샷
```

**권위(authority)**: 호스트 클라이언트가 게임 상태의 기준.
- 다른 플레이어는 "요청"(예: 뼈 회수, 퍼즐 조작)을 broadcast → 호스트가 규칙 검사 후 "확정" 이벤트를 broadcast → 모두 같은 결과 반영.
- 호스트가 나가면 presence에서 가장 먼저 들어온 플레이어가 호스트 승계, `rooms.state` 스냅샷으로 복구.

## 3. 메시지 설계

| 이벤트 | 보내는 쪽 | 빈도 | 내용 |
|---|---|---|---|
| `pos` | 각 플레이어 | 10–12Hz, 움직일 때만 | `{id, x, y, vx, vy, facing, anim}` → 받는 쪽은 100ms 지연 보간 |
| `act` | 각 플레이어 | 이벤트 | 스캔·조작·피격 애니메이션 표시용 |
| `req` | 비호스트 | 이벤트 | `{type:'pickup'|'interact'|'puzzle', ...}` |
| `ok` | 호스트 | 이벤트 | 확정 결과 `{seq, type, payload}` (seq로 순서 보장·중복 무시) |
| `sync` | 호스트 | 2초마다 + 입장 시 | 전체 상태 스냅샷(뼈, 플래그, 잠금, 퍼즐 진행) |

퍼즐 동시 조작: 조각을 잡는 순간 `lock{pieceId, owner}`를 호스트가 확정 → 다른 플레이어 화면에서 그 조각은 잡힌 사람 색 테두리로 표시, 놓으면 해제.

## 4. 방 흐름
1. **방 만들기**: 6자리 코드 생성(혼동 문자 제외) → `rooms` 행 insert → 채널 구독.
2. **코드로 참가**: 코드 입력 → 채널 구독 → presence 등록(색상 중복 시 다른 색 자동 제안).
3. **로비**: 색상 선택, 준비 토글, 역할 미리보기. 호스트만 시작 가능(전원 준비 시 활성화).
4. **게임**: 위 메시지로 동기화. 1명이 퍼즐을 풀면 `ok` 이벤트로 모든 화면에 잠금 해제·연출이 즉시 반영.
5. **결과**: 개인/팀 기록을 함께 표시.

## 5. 협동 미션(역할) 설계 — CH1 예시
| 역할 | 담당 |
|---|---|
| A 판독 | X-ray 판독기에서 지표를 읽어 다른 사람에게 단서 전달(같은 화면을 볼 수 없음) |
| B 조립 | 뼈대 복구 테이블에서 조각 배치 |
| C 검증 | 관절 보정 장치에서 정렬 검증 |
| D 보안 | 정전 중 차단기·출입문 조작, 위험 구역 우회 안내 |

인원이 적으면 역할을 합치고, 솔로는 지금처럼 순차 수행.

## 6. 데이터·보안
- 테이블 `rooms(code pk, host_id, state jsonb, updated_at)`, 익명 로그인(Anonymous Sign-in) 사용.
- RLS: 방 참가자만 해당 행 읽기, 호스트만 `state` 갱신.
- 개인정보 저장 없음(닉네임·색상만).
- 무료 요금제의 동시 접속·메시지 한도를 확인하고 `pos` 빈도를 조절해야 함.

## 7. 구현 순서 (예정)
1. Supabase 프로젝트 생성 + 키를 환경 변수로 주입(공개 anon key만 클라이언트에 사용)
2. 로비 UI(방 만들기/코드 참가/색상/준비)
3. 위치 동기화 + 보간, 원격 플레이어 표시(같은 스프라이트 아틀라스 재사용)
4. 호스트 권위 이벤트(회수·잠금·퍼즐) + 스냅샷 재접속
5. 퍼즐 조각 잠금 + 역할 미션
6. 2~4인 실제 기기 테스트(iPad 2대 + PC)
