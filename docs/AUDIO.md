# 사운드 현황 (CH1·CH2)

**모든 소리는 Web Audio API로 실시간 합성합니다. 오디오 파일(mp3/ogg/wav)은 하나도 없습니다.** (`app/src/core/audio.ts`)
아래 "확인" 열은 기초·심화 전체 플레이 자동 테스트(헤드리스 Chromium)에서 `Audio.played` 카운터로 **실제 호출된 것을 확인**한 것입니다. 소리가 귀에 들리는 품질·음량은 사람이 듣고 확인하지 않았습니다.

## 1. 배경음 (music 버스)
| 모드 | 사용 장면 | 구성 | 확인 |
|---|---|---|---|
| `title` | 타이틀, 결과 화면 | 마이너 아르페지오(84 BPM) + 밴드패스 노이즈 | ✅ |
| `ambient` | **CH1** 탐색 중 | 마이너 아르페지오(70 BPM), 저음 패드 | ✅ (CH1 로그) |
| `lab2` | **CH2** 탐색 중 (v3에서 추가) | 도리안 음계, 76 BPM, 근수축 같은 저음 "툭" 펄스 + 숨소리 패드 | ✅ (CH2 로그) |
| `tension` | CH1 정전 / CH2 전기자극 과부하 이벤트 | 128 BPM 톱니파 펄스 | ✅ |
| 앰비언트 드론 | 타이틀부터 계속 | 저음 톱니파 드론 + 공조 소음 | ✅ (startAmbient) |
| 경보 루프 `alarm` | 시작 봉쇄 연출, 정전·과부하 이벤트 | 880/660 Hz 교대 | ✅ |
| 심장박동 `heartbeat` | 이벤트 남은 시간 20초 이하 | 저음 2연타 | 코드 연결됨 (테스트는 20초 전에 해결해 미발생) |

**CH1과 CH2 배경음은 서로 다릅니다** (`ambient` vs `lab2`). v2까지는 같은 `ambient`였습니다.

## 3. 설정
| 기능 | 상태 |
|---|---|
| 전체 음량 / 배경 음악 / 효과음 슬라이더 (0–100 %) | 있음 (설정 화면, 저장됨) |

## 4. iPad Safari
- iOS Safari는 사용자 터치 이벤트 안에서만 AudioContext를 시작/재개할 수 있습니다. Phaser 입력 콜백이 그 안에서 실행된다는 보장이 없어, **v3에서 네이티브 `touchend`/`pointerup`/`click`/`keydown` 리스너로 unlock·resume을 추가**했고, 탭 전환·잠금 후 돌아오면 `visibilitychange`에서 재개를 시도합니다.
- **미검증**: 실제 iPad Safari에서 소리가 나는지, 무음 스위치(벨소리 끔) 상태에서 Web Audio가 음소거되는지, 블루투스 출력 지연 등은 확인하지 않았습니다. 헤드리스 Chromium에서는 AudioContext 상태가 `running`인 것까지만 확인했습니다.

## 5. 없는 것 / 추가하면 좋은 것
- 사람이 작곡·녹음한 음악·효과음(현재는 전부 합성음) — 퀄리티 향상에 가장 효과적
- CH2 전용 효과음: 근육 연결 시 "근수축" 소리, 전기자극 장치의 전극 방전음(현재는 공용 zap), 운동 재현 시 관절 각도에 따른 피드백음
- 퍼즐별 배경음 레이어(집중 모드), 결과 화면 전용 곡
- 접근성: 시각 효과와 함께 쓰는 소리의 자막/진동 대체(iPad는 진동 미지원)
